# 公开发布与自动更新

版本1.1.0起支持从公开GitHub仓库的Release获取更新，当前版本1.1.1。默认发布仓库为 baozibao728-cmd/jingxu-workbench，公开源码与更新包不含Key和用户数据。

## 使用者

进入左下角“接口设置”→“软件更新”，填写发布者提供的“账号/仓库名”。默认开启自动检查和空闲自动安装：启动3秒后检查，运行期间每30分钟检查；有任务时等待，空闲后重试。也可关闭自动安装，自己点“立即检查”与“安装新版本”。目前公开仓库可用，私有仓库访问认证尚未接入。

安装前校验路径、版本号和每个文件的SHA-256；旧程序备份在 `data/program-backups/`。只替换程序文件，绝不删除或覆盖 `.env`、整个 `data/`、用户剧本、图片、视频、历史、自定义系统提示词、并发和厂商配置。中途写入失败会回滚已写入的程序。已有任务结束后再更新，更新成功后服务自动重启，页面重新连接。

目前本地模拟测试通过；仓库发布后，仍需验证第一次真实GitHub下载更新。发布仓库的维护者能够发布新程序，请填写自己信任的仓库。

## 厂商配置

文字、图片和视频分别选择已保存的厂商方案，也可新增。Key框不回显；编辑同一方案时留空保留，新方案不自动借用另一方案的Key。原 `.env` 不改写，新方案保存到 `data/projects/provider-settings.json`（权限600），更新时保留。配置更改保留连接历史，已提交任务继续使用原厂商连接查询。

支持DeepSeek/OpenAI Chat Completions、Grsai原生、OpenAI Images纯生图、菲阳原生，以及HTTP JSON自定义适配。需要填写：方案名、协议、HTTPS基础地址、模型ID、Key、认证头及前缀、超时；兼容协议可填提交路径。自定义JSON还需按供应商文档填写提交/查询/上传路径，请求模板、响应字段和状态映射、参考图上传方式与引用标记。视频需声明时长、分辨率和参考图限制。供应商需支持这些协议或完成对应适配；动态签名等专有原生协议不能仅改地址就通用。

OpenAI Images兼容模式目前只接纯生图；尺寸默认横版1536×1024、竖版1024×1536，实际尺寸以供应商为准，可自行设置。用户原Grsai协议仍支持原来的比例与参考图参数。带参考图编辑或其他协议请按供应商规范另配JSON适配。

## 发布者

先把 `outputs/镜序工作台_GitHub源码包.zip` 解压后的内容放入公开仓库。这个源码包按白名单打包，不带 `.env`、`data/`、旧共享Key包、用户资产清单或真实联调记录。不要直接把整个工作目录上传。

发布步骤：

1. 修改 `package.json` 的版本号，例如 `1.1.1`。
2. 运行 `npm test`，再运行 `node scripts/build-update.mjs`，产出不含用户数据的 `outputs/jingxu-update.json`。
3. 在GitHub创建对应标签 `v1.1.1` 的Release，并附上该JSON；只推送源码而没有Release不构成更新。
4. 源码包附带 `.github/workflows/release.yml`，启用Actions后推送匹配版本的 `v*` 标签，可自动测试、构建并发布。流程只使用GitHub自动提供的发布令牌，不需要生成模型的Key。
5. 告知使用者“账号/仓库名”，让每台电脑保存一次。以后发布新版本即可自动检查。

`jingxu-update.json` 包含程序文件的base64与摘要，属于可发布程序包。可在Windows/macOS安装；Node仍需22.9以上。更新不执行用户数据迁移删除操作；今后若修改数据格式，应继续保留旧字段和文件。


## 1.1.1 模型列表与整剧重解析

“一键AI对齐后续”已移除，原位置统一使用“全部重新解析分镜”。整剧按原文顺序分段重新生成提示词，复用资产图；全部成功才替换，旧分镜与成片保留，失败可继续。仅调用文字模型，不自动生成图片或视频。单条编辑与人工确认衔接仍可用。

设置→接口配置：文字、图片、视频的每个厂商方案均可保存多个模型。每行填写模型ID，可加“| 显示名称”，再在“当前使用模型”下拉框选择并保存。图片默认恢复原六个预设（Image2、2.6、VIP、2.5、Flare、Sunburst），也可添加自定义型号。预设名称不代表厂商当前一定开放，实际支持以供应商为准。资产区标题旁可直接切换生图模型，切换不触发生成；有任务时需等待完成后切换。已有Key与记录保持原样。
