# 短剧工作流接入约定

按用户 2026-11-10 本次对话确认的渠道准备。当前为接口基础层，不是已完成的一键出片软件。

## 已确定的渠道

| 用途 | 服务 | 约定 |
|---|---|---|
| 剧本处理、资产提取、分镜脚本 | DeepSeek | 独立 Key，具体模型可配置 |
| 人物、道具、场景及分镜图片 | 用户提供的 Grsai 中转站 | 仅接 Grsai 的 GPT Image 系列；不用 OpenAI 官方生图地址或 Key |
| 视频片段 | 菲阳动漫 fydmai.com | 独立 Key；模型及素材限制按账号返回选择 |

## Grsai 原生接口

文档：https://qmy27nhsd9.apifox.cn/452409160e0

查询文档：https://qmy27nhsd9.apifox.cn/452409577e0

已读取公开页面及导出的 OpenAPI，原文保存在 `sources/grsai-gpt-image.md` 和 `sources/grsai-result.md`。文档快照中的模型名和说明代表读取时状态，不保证账号实际可用。

- 全球节点 `https://grsaiapi.com`；国内节点 `https://grsai.dakka.com.cn`。
- `Authorization: Bearer <GRSAI_API_KEY>`。
- 提交：`POST /v1/api/generate`，字段 `model`、`prompt`、`images`、`aspectRatio`、`quality`、`replyType`、`outputFormat`。
- `images` 是 URL/base64 字符串数组。`localImageReference()` 可将本地图片转换为 data URL；中转站是否接受带 MIME 前缀的 data URL 还需实测。
- 基础层采用 `replyType: "async"`；保存任务 ID 后，调用 `GET /v1/api/result?id=...` 查询。
- 上游状态为 `running / succeeded / failed / violation`。
- 成功结果在 `results[].url` 中。文档注明：最终结果出现后任务查询有效期为两小时。上层调度器应及时下载并落盘。
- vip/flare/sunburst 型号的比例参数需要像素值。基础层对 1:1、16:9、9:16 做文档内尺寸转换，其余比例应填写明确像素值。
- 具体型号保留空配置；由用户选择后填写，不能自动替换成官方型号或静默切到其他渠道。

## 菲阳动漫：目前依据用户截图

来源为用户本次提供的三张 API 文档截图。公开首页可访问；本次公开文档页未取得完整正文，以下不冒称在线原文已验证。

- 根地址 `https://fydmai.com`，鉴权 `Authorization: Bearer <FYDMAI_API_KEY>`。
- `GET /v1/models` 获取可用模型、参数及限制。返回对象的详细结构还需拿到账号后确认。
- `POST /up/check`，JSON `{ "sha256": "<hex>" }`；存在时响应含 `exists: true` 和 `assetId`。
- 不存在时 `POST /up/`，multipart 文件字段固定为 `file`，取得 `assetId`。
- `POST /v1/videos`，字段为 `model`、`prompt`、`duration`、`resolution`、`aspectRatio` 和 `referenceImages: [{ "assetId": "..." }]`。
- `GET /v1/videos/{task_id}` 查询；截图状态为 `queued / in_progress / completed / failed`。
- 完成后响应直接包含 `url`；截图注明链接有效期 24 小时，应及时下载。下载链接不带 API 鉴权头。
- 视频参考素材可同时包含图片和音频：图片通过 `referenceImages`，音频通过 `referenceAudios`。本地语音库的 MP3 仅在用户在分镜中勾选、并在生成前确认后上传；自定义厂商必须配置能接收音频文件的上传适配器。音频参考用于视频模型输入，视频生成完成后不会自动把它作为最终配音混入成片。

## 自动引用的边界

内部使用 `{{ref:稳定资产ID}}` 模板，绑定具体资产版本和上传后的 `assetId`。引用顺序和 `referenceImages` 必须由同一份绑定生成。

**截图没有明确给出提示词内 @ 标记的语法和它与 referenceImages 的对应规则。** `compileReferences()` 因此要求显式传入已经确认的转换函数；未配置语法就拒绝编译，视频接口也拒绝含未编译占位符的提示词。不把本地模板当成视频模型已经支持的语法。

后续真实联调补充：已读取菲阳公开网页客户端 `main.js` 和 `host-web.js`。客户端采用 `@上传文件名.扩展名` 标记素材，并把实际素材按顺序上传为 `referenceImages`；代码注释说明服务端会继续绑定成 `@imageN`。已据此提供 `fydmaiFilenameTag()`。这是客户端行为和接口约定的核对，尚不代表视频成片中的引用效果已经验证。

`GET /v1/models` 在本次账号上只返回模型ID；详细限制实际从网页客户端使用的 `GET /caps` 读取。已核对 `seedance2.0` 上架、480p、4～15秒、最多9份参考素材，本次审阅请求明确只填5秒。

1. 三家 Key、DeepSeek/Grsai 的具体模型、菲阳模型列表及参数结构。
2. Grsai 从参考主图生成派生图的真实保持效果，data URL 支持情况。

4. 后台持久化任务队列、重启恢复、结果自动下载归档、额度与并发控制。
5. 正式剧本/资产/分镜规则及结构校验、资产版本追踪、受影响镜头更新。
6. 操作界面、完整一键工作流与整集合成。

上列1～3项的当前进展以 [真实联调记录](真实联调记录.md) 为准；DeepSeek/Grsai Key、文本生成、生图和菲阳图片上传现已验证，视频生成仍待用户确认后进行。

提交超时可能已经建立远端计费任务。基础层不自动重复 POST；上层要记录“提交结果未知”并核对远端状态。下载函数可调用，但当前没有自动轮询后台或自动出片承诺。
